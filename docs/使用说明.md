# GregNuovo 使用说明

> 适用版本：MC 1.20.1 / Forge 47.4.10 / GTM 1.20.1-7.3.0 / AE2 15.4.x
> 本模组**不添加任何方块和物品**，它只是让「AE2 样板供应器 / GTM ME样板总成」与「GT 机器」配合得更好。

---

## 1. 安装

1. 前置（整合包里应该已经有了）：
   * GregTech Modern 7.3.0（1.20.1）
   * Applied Energistics 2 15.4.x
   * GTM 前置：LDLib、Architectury、Configuration；AE2 前置：GuideME
2. 把 `GregNuovo-1.0.1.jar` 放进实例的 `mods/` 目录：

   ```
   E:\pcl2\.minecraft\versions\<你的实例>\mods\GregNuovo-1.0.1.jar
   ```

   客户端与服务端都要放（多人服务器只需服务端也有，客户端也放可避免不一致）。
3. **完全重启游戏**（Mixin 只在启动时注入，换了 jar 必须重启，不能只回主菜单）。
4. 启动后 `config/gregnuovo-common.toml` 会自动生成；进游戏执行 `/gregnuovo status`（需 OP / 单人需开作弊）应能看到计数表。

## 2. 三种接线方式（先确认你是哪种）

| 你的结构 | 说明 | 电路写到哪 |
| --- | --- | --- |
| **A. 单方块机器** | AE2 样板供应器紧贴 GT 机器（研磨机、组装机…） | 机器自己的电路槽 |
| **B. 多方块 + 输入总线** | 样板供应器紧贴 **输入总线 / ME输入总线**，总线在多方块结构上 | 该总线的电路槽 |
| **C. 多方块 + ME样板总成** | 把 **ME样板总成** 装在多方块结构上，样板放进总成里 | 该样板槽自己的电路 |

> 样板供应器与 ME样板总成 都可以是**方块**也可以是**线缆上的部件**，两种都支持。

机器产出的物品要回到 ME 网络（这是 AE 自动合成的前提）：
* 单方块机器：GT 机器会自动输出，紧贴一个 **ME 接口**（或让样板供应器/ME 输出总线接住）即可；
* 多方块：输出总线后面接 **ME 输出总线** 或 **ME 接口**。

## 3. 五项功能怎么用

### 3.1 编程电路自动写入（需求2）

有两种用法，**任选其一都行**：

**用法 A（推荐，什么都不用编）：样板里不放电路。** 模组会看这台机器/总线能跑的 GT 配方，如果该配方需要编程电路，就**自动**把机器设成对应编号再推料。（=`circuit.autoDetectFromRecipe=true`，默认开）

**用法 B：把编程电路当作样板的一个「输入材料」编进样板。**
1. 用 AE2 的**样板编码终端**编码处理样板；
2. 在**输入格**里放入 `gtceu:programmed_circuit`（编程电路，右键可调编号，0–32），和其他原料放在一起；
3. 输出格照常写产物。

两种方式的共同效果：

* 模组在**推料之前**把电路写进机器/总线的电路槽；
* 电路**不会**作为物品被推送到机器里；
* 默认（`circuit.stockless=true`）**不需要网络里有电路备货**，也不会消耗电路；
* 如果配方**不需要**电路、样板里也没写 → 推料前把该机器电路槽**清零**（`clearWhenAbsent`），避免残留电路串味；
* 合成结束后会清掉模组写入的电路（`clearAfterCraft`）。

> 用法 B 的好处：同一台机器上多个只有电路不同的配方可以放在**不同样板**里，互相不干扰；
> 用法 A 的好处：不用手工维护电路编号，配方改了也会自动跟上。

### 3.2 不消耗物品自动回网（需求1）

**要做的事：把模具/催化剂等按正常方式编进样板输入，什么都不用额外设置。**

* 配方跑完、机器回到空闲约 1 秒后，本次投进去但**没被消耗**的物品会自动回到 ME 网络（终端里能看到）；
* 多方块走 ME样板总成时，等价于自动按下总成上那个「退回全部」按钮。

注意两点：

1. AE2 的合成计划会**按每一次合成**计算输入数量，所以一次作业要用 N 次模具时，
   网络里最好备够 N 个（用完会如数退回，不会被吃掉）。编程电路不受这条限制。
2. **ME输入总线**结构下，喂给多方块的物品本来就是 AE 网络的视图（不落地），
   notConsumable 的模具从头到尾都在网络里 —— 这时“没有余料可退”是正确的（`/gregnuovo status` 会显示 `退料扫描` 有计数、`退回余料` 为 0）。

取料会依次尝试：GT 机器内部处理槽 → AE 存储 → Forge 物品栏，因此单方块机器、普通输入总线、ME输入总线都能覆盖。

### 3.3 概率产物：需要就一直补料（需求3）

**要做的事：把概率产物也写进样板的输出格。**

例：配方是「主产物 A 100% + 副产物 B 50%」→ 样板输出格里放 A 和 B 两个物品。

然后在终端请求 **B**：模组会自动从 GT 配方判断出 B 是概率产出，只要这次没出 B（而任务还需要 B），机器空闲后会**自动再补一份材料**重跑，直到 B 出来为止。

* 默认**不限次数**（`chance.maxRetries=0`），也可设上限；
* 重试间隔 `chance.retryIntervalTicks`，默认 20 tick（1 秒）；
* 每次重试都是真实投料，会消耗材料——这是需求本身的语义。

### 3.4 不需要的概率产物不等待（需求4）

同一块样板（A + 50%B），如果你这次**只要 A**：

* A 到手，合成任务立刻结束；
* 不会为了等 B 而卡住、也不会额外补料重试；
* 顺手产出的 B 会直接进网络存储，不浪费。

### 3.5 副产物可被 AE 读取与自动合成（需求5）

样板输出格里写出的**每一个**产物（不只是主产物）都会被登记为「可自动合成」：

* 在终端里请求副产物 B，AE 就能找到这块样板并规划合成；
* 配合 3.3 的重试，B 最终会被真的做出来；
* 开关：`chance.byproductCraftable`（默认开）。

## 4. 配置项（`config/gregnuovo-common.toml`）

```toml
[GregNuovo.circuit]
	injection = true            # 需求2 总开关
	stockless = true            # 电路不需要网络库存（临时构造、推送时丢弃）
	autoDetectFromRecipe = true # 样板没编电路时，从 GT 配方自动推断所需电路
	clearWhenAbsent = true      # 配方不需要电路时 → 机器电路槽清零
	clearAfterCraft = true      # 合成结束后清除本模组写入的电路

[GregNuovo.leftover]
	enabled = true            # 需求1 总开关

[GregNuovo.chance]
	byproductAware = true     # 从 GT 配方推断哪些是概率产物
	byproductCraftable = true # 需求5：副产物也登记为可合成
	retry = true              # 需求3 总开关
	maxRetries = 0            # 0 = 不限次数
	retryIntervalTicks = 20   # 重试间隔（tick）

[GregNuovo.misc]
	startTimeoutTicks = 1200  # 推送后机器一直不开工就放弃跟踪
	debugLog = false          # 打开后日志会写每一步判断
```

改完配置**需要重启游戏或 `/reload` 后重新进存档**（Forge 通用配置在启动时读取）。

## 5. 自检与排查

1. `/gregnuovo status`（OP）—— 一眼看出问题出在哪：

   ```
   样板供应器钩子=… 样板总成钩子=…     ← 为 0：注入没生效（看日志有没有 mixin 报错）
   找到 GT 目标=… 未找到=…             ← 未找到 > 0：日志会列出旁边的方块类型
   写入电路=…（样板编码=… 配方推断=… 无电路槽=…） 清除电路=…
   机器开工=… 配方完成=… 清理次数=…     ← 为 0：机器根本没跑起来（多半是配方没匹配上）
   退回余料=… 退料扫描=… 补料重试=…   ← 需求1 / 需求3（扫描>0 但退回=0 → 确实没有余料可退）
   副产物登记样板=… 剔除多余等待=…      ← 需求5 / 需求4
   挂起记录（最多 5 条）：…            ← 卡住的合成现在处于哪个阶段、电路是多少、推了什么
   ```

2. 把 `misc.debugLog` 改成 `true`，复现一次，看 `logs/latest.log` 里 `GregNuovo：` 开头的行。
3. 常见情况：

| 现象 | 原因 |
| --- | --- |
| 全部计数都是 0 | jar 没生效：确认放进了 `mods/`、重启过游戏、日志里没有 `Mixin apply failed` |
| `未找到` 一直涨 | 供应器旁边不是 GT 机器/零件（比如中间隔了接口、线缆、空气）——紧贴它 |
| `写入电路` 一直 0 | 该配方本来就不需要电路（正常），或目标没有可写电路槽（日志会 WARN 说明，此时电路按原版当物品推送） |
| `机器开工=0` + `清理次数>0` | 配方没匹配上：检查电路编号、机器等级/电压、输入是否齐全 |
| 余料一直不回 | 机器还没真正空闲过（一直在跑），或余料不在被推送的那台方块里 |
| 概率产物不重试 | 该输出没被判断为概率产出（样板输出与 GT 配方对不上），或任务其实不需要它 |

更详细的排查清单见 `docs/需求实现说明.md` 第 10 节。
